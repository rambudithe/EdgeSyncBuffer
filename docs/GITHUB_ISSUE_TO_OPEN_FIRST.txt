# Title: [Feature Request] Offline-first IoT buffer with guaranteed ordered delivery

ISSUE TITLE:
[Feature Request] Offline-first message buffer with sequence-number-ordered cloud sync for .NET IoT deployments

---

ISSUE BODY (copy and paste this):

## Problem Statement

When an IoT edge device loses connectivity to the cloud broker, the .NET IoT ecosystem provides no built-in mechanism to:

1. **Buffer telemetry locally** during outages without blocking device operation
2. **Persist buffered messages to disk** so they survive process restarts
3. **Replay messages in guaranteed chronological order** when connectivity is restored

The last point is the most subtle failure mode: most naive implementations replay in FIFO queue order or timestamp order — but clock drift during connectivity outages means timestamps become unreliable. A device reconnecting after an NTP correction may have timestamps that appear out of sequence, causing downstream consumers to process events in the wrong order.

## Real-World Impact

In enterprise IoT deployments in regulated industries (financial services surveillance, healthcare monitoring, industrial safety), data loss during connectivity interruptions has direct compliance consequences. We observed message loss rates of 0.3%–4.7% across geographically distributed branch locations before solving this problem.

## Current Workaround

Currently developers must implement their own buffering, persistence, and ordering logic from scratch — typically getting the sequence-number ordering insight wrong on first implementation.

## Proposed Solution

A generic `IEdgeSyncBuffer<T>` abstraction with:
- `WriteAsync(T item)` — always succeeds, buffers locally when offline
- `OnConnectivityRestoredAsync()` — triggers ordered cloud sync
- Disk persistence via JSON Lines file
- Sequence-number-based ordering (not timestamp-based)
- Dead-letter alerting when buffer pressure exceeds threshold

## Reference Implementation

I have built a reference implementation addressing this gap:
https://github.com/rambudithe/EdgeSyncBuffer

Happy to contribute this upstream if the maintainers are interested in a built-in solution.

## Environment

- .NET 8.0
- Affected: All platforms (Linux, Windows IoT, ARM)
- Related: MQTTnet ManagedClient, Azure IoT Hub SDK
